The architecture, the TOGAF way

TOGAF's ADM separates concerns into Business, Data, Application, and Technology architecture. Each layer maps to exactly one part of this platform, and each diagram below shows one or two layers — never all four at once.

Business architectureSelf-directed global algorithmic trading: thousands of strategies, one book, three regions, one small operator team. Channels: web portal, iOS and Android apps, partner APIs, admin console.
Application architectureFive custom components only — trading cell, alpha-factory strategies, portal and APIs, wallet policy engine, signer. Everything else is a managed Google service. Diagram 2 is this layer.
Data architectureOne owner per dataset and no custom databases: the journal for trading truth, Spanner for the financial ledger, Bigtable for time series, BigQuery for analysis, WORM storage for evidence. Diagram 3 is this layer in motion.
Technology architectureGoogle Cloud in three regions with Interconnect in every venue metro; Compute Engine for the microsecond path, one GKE Autopilot cluster per region for everything elastic, Cloud Run for everything stateless.
  • Global control, regional execution — a region keeps trading if the control plane disappears
  • Managed by default, custom by exception — code exists only where it earns alpha or signs money
  • Hot-path isolation — nothing queued, proxied, orchestrated, or persisted inline with an order
  • Explicit ingress, explicit egress — one front door, one back door, everything else denied
  • Immutable financial record — append-only double-entry ledger; balances are derived, never stored
  • Zero-trust identity — every human has MFA and just-in-time roles; every workload has an identity, no keys
  • Security at FIPS grade — wallet keys are created and used inside Cloud HSM (FIPS 140-2 Level 3) and never leave
  • Scale by replication — more cells, more regions, more pods; never a bigger anything
How to read the diagrams. Straight lines only: flows run top to bottom or left to right with square corners. Solid arrows are data and traffic; dashed purple is control; dashed red is a halt. Box color is trust zone, the corner tag is who builds it (GOOGLE or CUSTOM), and dashed containers are boundaries — a region, a cluster, a perimeter.
