## 4. What this wave moved, and what it did not

Seven commits since the last re-score, oldest first.

### 4.1 `ece7602` — the ECB rates. **Does not move Ingestion's fifth capability.**

This is the hard one and it is argued rather than asserted.

**The capability's own words.** `completion-plan.md:163` names it **"one live
source sustained"**. The bar word is *sustained*, and the same document defines
it: the Phase 1 exit is "7 days stable streaming, statistics converged, no raw
stream retained" (`completion-plan.md:136`).

**What `ece7602` produced.** Real ECB reference rates, from the real vendor,
through the unmodified `qip-api` binary — licensing gate, connector,
`Platform::observe`, one `POST /cycle`, the hash chain — with dedup holding on a
re-poll twenty minutes later. That is a real result and the first of its kind in
this repository. Its own record does not overstate it
(`docs/ops/live-source-frankfurter-2026-09-06.md:246`): **"This is one poll,
twice. Not a stream, not seven days, not an SLA."**

**Three reasons it does not close the capability, in descending order of
strength:**

1. **"Sustained" is unmet, and no repository test can meet it.** Twenty minutes
   is not seven days. This capability is a MEASURED-bar capability by
   construction — like Layer 6's "anything applied and observed", it names an
   operational fact, and no `cargo test` can establish it. A wave that produces
   a twenty-minute run has moved toward it and has not reached it.

2. **It does not reach MEASURED under the bar this scorecard states.**
   `PROJECT-PLAN.md:69` defines MEASURED as "real cloud evidence, not a
   repository test". There is no cloud in this run. It was, in the record's own
   words, "a local Python bridge on loopback is not Envoy … this run was a
   process on a build container"
   (`docs/ops/live-source-frankfurter-2026-09-06.md:242-245`), and the transport was
   an uncommitted 100-line Python listener standing where an unapplied Envoy
   proxy will go. The vendor half was real; the transport half was a fixture
   wearing the proxy's shape. `.claude/rules/domains/data-and-streaming.md` says
   it in terms and the record quotes it: *a connector proven in a session behind
   a local bridge is not proven in a deployment.*

3. **It does not reach TESTED either, and this is the part most likely to be
   mis-scored.** There *is* a named test —
   `the_connector_feed_fetches_live_reference_rates_that_were_already_knowable_when_they_arrived`
   — and it passed with real vendor values printed. But
   `live_connectors.rs:1-8` states that "with none set every test here prints
   why it was skipped and passes". In `make check`, in CI, and in every
   unattended run, that test passes without opening a socket. A test that passes
   vacuously in the gate is precisely the class
   `.claude/rules/architecture/01-testing-strategy.md` warns about — it "passes
   forever and guards nothing". Citing it as the capability's TESTED evidence
   would put a green tick on a check nobody runs.

**The competing reading, and why it loses.** `PROJECT-PLAN.md:79` paraphrases
this capability as "a live source proven end to end". Under that paraphrase
alone, `ece7602` has a real claim: licensing gate → connector → `observe` →
cycle → hash chain is end to end by any ordinary reading, and it would take the
headline to 55/71 (77.5%). It loses for two reasons. The paraphrase silently
drops *sustained*, which is the capability's whole content — and the paraphrase
is not the capability; `completion-plan.md:163` is. And "end to end" for *this*
platform's architecture includes the egress proxy, which was replaced by a
stand-in the commit deliberately refused to commit "because committing a fake
egress proxy invites someone to mistake it for the real one".

**Verdict.** Ingestion stays **4/5** at the TESTED bar and **0/5** at the
MEASURED bar. What `ece7602` changed belongs in the row's prose, not its
numerator, and it is worth stating exactly: *for the first time, a capability in
the investment loop ran against real data outside `cargo test`.* The scorecard
has no level for "run once, off-deployment, through a stand-in", and inventing
one would be worse than saying so.

**Also in `ece7602` and separately scored:** every committed universe record
gained a stated liquidity block (`grep -c '"liquidity"' data/datasets/universe.json`
→ 6, against `grep -c '"object_id"'` → 6). That hardens the illiquid-valuation
and liquidity-ladder engines, both already counted. No move.

## 5. Where the existing scorecard is wrong, not merely stale

### 5.1 The Valuation denominator is not §16.1's six. **This is an error, not staleness.**

`completion-plan.md:165` defines the denominator as "six engines (§16.1)".
Blueprint §16.1 (`docs/architecture/algorik-blueprint-v10.1-source.md:1259`)
names: term structure · credit · **volatility surface** · illiquid valuation ·
cashflow and commitments · **corporate actions**.

`PROJECT-PLAN.md:81` enumerates a different six: term structure · credit ·
cashflow/commitments · illiquid valuation · **liquidity ladder** · volatility
surface. It has substituted the liquidity ladder — which §16.1 does not name —
for corporate actions, which §16.1 does name and calls "a prerequisite for
equities, not an enhancement".

The substitution is not neutral. It **adds a wired engine and removes an unwired
one**, so it inflates the fraction by exactly one:

| | Wired | Fraction |
|---|---|---|
| As the row counts it | term structure, credit, cashflow, illiquid, liquidity ladder | 5/6 = 83% |
| Against §16.1 | term structure, credit, cashflow, illiquid | **4/6 = 67%** |

**Correct figure: 4/6 wired, 67% not 83%.** Evidence for the swapped-in and
swapped-out members is in §2's Valuation table:
`Position::apply_adjustment` (`qip-portfolio/src/position.rs:269`) has exactly
one caller and it is `qip-portfolio/tests/accounting.rs:324`, so no production
path applies a split or a dividend to a position.

The liquidity ladder is genuinely wired and genuinely valuable. It is a seventh
engine, and counting it inside a denominator defined by §16.1 makes the
denominator no longer mean what its citation says.
