## The 4 Blocked Requirements

These four requirements cannot be implemented because they require actual external capital movements with no simulated equivalent:

### CAPITAL-015: FX Funding Adapter
**Requirement:** Borrow currency from counterparty  
**Blocker:** Requires real FX counterparty to actually fund and track foreign-exchange borrowing obligations  
**Why No Simulation:** No sandbox currency broker exists that simulates cross-border borrowing with real settlement mechanics  
**Paper Boundary Layer:** LIVE_CAPITAL + EXTERNAL_ACTION flags; no Terraform path, no composition root path, type system prevents ordering

### CAPITAL-016: Borrow/Lend Adapter
**Requirement:** Borrow or lend cash/securities with counterparty  
**Blocker:** Requires real counterparty to open actual repo or securities-lending obligations  
**Why No Simulation:** Unlike simulated order venues, securities lending requires counterparty credit assessment, custodial account setup, and real settlement  
**Paper Boundary Layer:** LIVE_CAPITAL + EXTERNAL_ACTION flags; no Terraform path, no composition root path, type system prevents ordering

### CAPITAL-017: Repo Adapter
**Requirement:** Finance position through repurchase agreement  
**Blocker:** Requires real repo counterparty to accept collateral and provide funding  
**Why No Simulation:** Repo settlement, haircut mechanics, and collateral substitution require real counterparty agreement  
**Paper Boundary Layer:** LIVE_CAPITAL + EXTERNAL_ACTION flags; no Terraform path, no composition root path, type system prevents ordering

### CAPITAL-018: Credit-Line Adapter
**Requirement:** Draw on committed credit facility  
**Blocker:** Requires real lender to have a live credit line with documented terms  
**Why No Simulation:** A credit line draw is a unilateral claim against a lender's commitment; it cannot be simulated without that commitment existing  
**Paper Boundary Layer:** LIVE_CAPITAL + EXTERNAL_ACTION flags; no Terraform path, no composition root path, type system prevents ordering

## Why These 4 Cannot Be Simulated

These four stand apart because they are **commitments by external parties**:

1. **Order execution** ← Can simulate: We own the simulated venue
2. **Position tracking** ← Can simulate: We control the journal
3. **Risk modeling** ← Can simulate: We generate the scenarios
4. **Borrowing capital** ← **Cannot simulate:** Counterparty controls whether the money shows up

An FX broker, securities lender, repo dealer, or credit facility lender are external entities. They decide whether to fund us, at what rate, with what collateral terms. We can:
- Record a *request* to borrow
- Check policy constraints (is borrowing permitted? within limits?)
- Refuse orders that would exceed borrowed capital

We **cannot**:
- Generate a real loan
- Have money appear in our accounts without a real counterparty
- Simulate the counterparty's response to a funding request

## Dependency Chain

If this system ever moves from paper-trading to live trading (architectural change requiring new ADR):

1. **Terraform** validator would need to allow live ceilings → new gate added
2. **Composition root** `deployable()` would need to permit live levels → policy change
3. **Type system** would expose live-venue types → new adapters added
4. **Only then** would CAPITAL-015 through CAPITAL-018 become viable

Until then, they remain architectural constraints by design.
