# Third-party images the platform adopts, mirrored into its own registry.
#
# Binary Authorization's default rule denies every image the platform's
# attestor has not signed, and that is the point of it — so a third-party
# image can run here in one of two ways: an exemption pattern that admits its
# upstream repository unsigned for ever, or an adoption. This file is the
# adoption path: `.github/workflows/vendor.yml` copies each source digest into
# the environment's Artifact Registry byte-for-byte, proves the digest survived
# the copy, scans it with the same gate the platform's own images pass, and
# attests it with the same attestor. The admission policy stays exactly one
# rule with no holes, and "which foreign code runs on this platform" is
# answered by this file's git history.
#
# Sources are named by digest, never by tag. A tag is whatever its owner says
# it is today; the digest is what was reviewed when the line was added. Moving
# to a new upstream version is a new digest in a new commit.
#
# Format: <source-ref-by-digest> <destination-path> <destination-tag>
# The destination lands at <registry>/<destination-path>:<destination-tag>
# in the target environment's registry. The tag is for humans browsing the
# registry; everything that matters references the digest.
#
# Two entries. Argo CD, Kargo, KEDA, cert-manager and redis were vendored for
# the GKE runtime and left with it (ADR 0024); nothing else third-party runs.
#
# The third adoption is pending: Google's managed-Prometheus collector for
# Cloud Run (`cloud-run-gmp-sidecar`), which modules/cloudrun runs beside the
# two brains once `metrics_collector_image_digest` names a digest mirrored
# from a line here as `vendor/cloud-run-gmp-sidecar`. No digest has been
# reviewed, so there is no line, no mirror and no sidecar —
# modules/observability/NOT-SCRAPED.md records the state.
#
# A fourth is scoped, not yet wired: OpenObserve (self-hosted metrics/logs/
# traces) as its own standalone Cloud Run service, requested this session.
# Its digest is mirrored below so the reviewed bytes exist in the registry,
# but nothing deploys it yet — two decisions still need a human, not this
# session: (1) OpenObserve is not another sidecar on an existing workload,
# it is a new *kind* of top-level workload this module was never built to
# host (every service `modules/cloudrun` deploys today gets its digest from
# this platform's own build→sign→attest pipeline via `images.tfvars`; a
# vendored image's digest comes from this file instead, a different
# lifecycle the module has no input for) — the kind of choice
# `.claude/rules/architecture/00-boundaries.md` says gets an ADR, not a
# same-session unilateral build; (2) OpenObserve's only persistent-storage
# backend is S3-compatible (`ZO_S3_*`, confirmed against its own docs) —
# there is no workload-identity-native GCS path, so durable storage means a
# GCS HMAC access/secret key pair, a class of static credential
# `.claude/rules/01-security-and-safety.md` says never to use ("Workload
# Identity Federation only... No downloaded service-account keys, ever").
# Ephemeral local storage avoids that but loses everything on every cold
# start, which is not a serious observability backend. Both are named here
# rather than one being picked silently.
