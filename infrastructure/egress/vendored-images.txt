# Third-party images the platform adopts, mirrored into its own registry.
#
# Binary Authorization's default rule denies every image the platform's
# attestor has not signed, and that is the point of it — so a third-party
# image can run here in one of two ways: an exemption pattern that admits its
# upstream repository unsigned for ever, or an adoption. This file is the
# adoption path: `.github/workflows/vendor.yml` copies each source digest into
# the environment's Artifact Registry byte-for-byte, proves the digest survived
# the copy, scans it with the same gate the platform's own images pass, and
# attests it with the same attestor. The admission policy stays exactly one
# rule with no holes, and "which foreign code runs on this platform" is
# answered by this file's git history.
#
# Sources are named by digest, never by tag. A tag is whatever its owner says
# it is today; the digest is what was reviewed when the line was added. Moving
# to a new upstream version is a new digest in a new commit.
#
# Format: <source-ref-by-digest> <destination-path> <destination-tag>
# The destination lands at <registry>/<destination-path>:<destination-tag>
# in the target environment's registry. The tag is for humans browsing the
# registry; everything that matters references the digest.
#
# Two entries. Argo CD, Kargo, KEDA, cert-manager and redis were vendored for
# the GKE runtime and left with it (ADR 0024); nothing else third-party runs.
#
# The third adoption is reviewed and REFUSED, not merely unreviewed: Google's
# managed-Prometheus collector for Cloud Run (`cloud-run-gmp-sidecar`), which
# modules/cloudrun would run beside the two brains once
# `metrics_collector_image_digest` names a digest mirrored from a line here as
# `vendor/cloud-run-gmp-sidecar`. The
# digest below was resolved from the registry v2 API and confirmed two ways —
# the `docker-content-digest` header for tag 1.9.2, and the sha256 of the
# manifest bytes that header names, which are equal — and the image was
# confirmed to be Google's own by reading
# `github.com/GoogleCloudPlatform/run-gmp-sidecar/confgenerator` and
# `confgenerator.Version=1.9.2` out of the entrypoint binary in its third
# layer. Unlike the two entries below it is a single
# application/vnd.docker.distribution.manifest.v2+json manifest, not a
# multi-arch index, so vendor.yml's child-manifest loop signs exactly one
# digest and the index/child admission failure recorded in that workflow
# cannot recur here.
#
# The review this paragraph was waiting for HAS NOW HAPPENED, and its result
# is that the line stays commented — for a reason, rather than for want of a
# reviewer. Recorded here because "resolved but nobody looked" and "looked at
# and refused" are different states, and the next person to reach for this
# adoption needs to know which one this is.
#
# Two of the three checks passed.
#
# The digest still resolves. The command below was re-run against the live
# registry and returned exactly the digest this paragraph names — the half
# that would have been silently false had the tag moved since resolution, and
# which no later gate looks at:
#
#   curl -sSI -H 'Accept: application/vnd.docker.distribution.manifest.v2+json' \
#     https://us-docker.pkg.dev/v2/cloud-ops-agents-artifacts/cloud-run-gmp-sidecar/cloud-run-gmp-sidecar/manifests/1.9.2 \
#     | grep -i docker-content-digest
#
#   docker-content-digest: sha256:ff1fc68871118f1032a3ce17e2b0abd703292e883989d220244330ebdf522fd1
#
# The configuration half holds too. The collector reads
# `/etc/rungmp/config.yaml` — the only such literal in its entrypoint binary,
# with no argument naming another — so a mirrored image scrapes nothing a
# person chose unless the module publishes a document at that path.
# `modules/cloudrun/main.tf` does: `collector_mount = "/etc/rungmp"` and an
# object named `config.yaml` beneath it.
#
# The third check refused it. vendor.yml run 11 mirrored the image and Trivy
# — the same gate the platform's own images pass — failed it:
#
#   run-gmp-entrypoint (gobinary)  Total: 1 (CRITICAL: 1)
#   rungmpcol (gobinary)           Total: 1 (CRITICAL: 1)
#   golang.org/x/crypto  CVE-2026-56854  CRITICAL  fixed
#     installed v0.54.0, fixed 0.55.0
#     golang.org/x/crypto/ssh: authentication bypass due to unenforced
#     source-address restrictions
#
# There is no patched release to move to. The registry's tag list carries
# 1.0.0 through 1.9.2 and nothing above it, so 1.9.2 is the newest Google
# publishes and every version behind it is older than the vulnerable
# dependency's fix. The adoption is therefore blocked upstream, not here.
#
# It is deliberately NOT waved through, and the temptation is worth naming
# because it is a good argument: the finding is in `x/crypto/ssh` and a
# metrics collector opens no SSH server, so it is very likely unreachable.
# That reasoning is how a scanner exception gets written, and an exception
# written once is an exception that outlives the release that needed it. This
# platform's rule is to fix rather than suppress; the fix here is Google's to
# ship. Re-check the tag list when observability is next picked up — a 1.9.3
# or 1.10.0 carrying x/crypto >= 0.55.0 makes this a one-line change.
#
# us-docker.pkg.dev/cloud-ops-agents-artifacts/cloud-run-gmp-sidecar/cloud-run-gmp-sidecar@sha256:ff1fc68871118f1032a3ce17e2b0abd703292e883989d220244330ebdf522fd1 vendor/cloud-run-gmp-sidecar 1.9.2
#
# The second entry, OpenObserve, IS deployed — this paragraph used to say it
# was not, and both decisions it was waiting on have been taken and recorded.
#
# (1) That a vendored image is a new *kind* of top-level workload, whose
# digest comes from this file rather than from `images.tfvars`, was the ADR
# `.claude/rules/architecture/00-boundaries.md` asked for: ADR 0028 adopts it,
# ADR 0030 records that its URL answers the internet anonymously on the
# owner's instruction, and ADR 0031 records why its credential is an
# environment value — that image carries no shell and no `_FILE` symbol, so
# the file mount the security rule mandates was satisfied and inert.
# `modules/cloudrun` gained `image_source = "vendored"` for exactly this
# lifecycle.
#
# (2) Storage was decided the other way: ephemeral, and the loss named rather
# than disguised. OpenObserve's only durable backend is S3-compatible
# (`ZO_S3_*`), there is no workload-identity-native GCS path, and a GCS HMAC
# key pair is the class of static credential
# `.claude/rules/01-security-and-safety.md` forbids outright. So a cold start
# loses every dashboard, which ADR 0028's own "what it costs" states.
#
# What follows from that is recorded in ADR 0033 and belongs here because it
# governs this line: nothing has yet sent telemetry to the deployed service,
# and before anything does it stops being reachable anonymously. An anonymous
# invoker is anonymous in both directions, and a store anyone may write to
# cannot be evidence for anything.
